# Contribution Guidelines

Thank you for helping improve this awesome list. Contributions are welcome,
especially links to high-quality resources that are useful to practitioners.

Please note that this project is released with a
[Code of Conduct](code-of-conduct.md). By participating in this project you
agree to follow it.

## What Belongs Here

- Tools, projects, libraries, frameworks, standards, practices, and case studies
  related to Chaos Engineering.
- Open source projects and commercial platforms. A commercial entry stays only
  when a reader can learn something concrete from it.
- High-quality articles, talks, books, guides, examples, and reference material.
- Resources that are actively useful, maintained, or historically important.
- Links with clear descriptions written in neutral language.

## What Usually Does Not Belong Here

- Pure marketing pages with little technical or educational value.
- Broken, unavailable, or private links.
- Very early projects without enough information for readers to evaluate them.
- Duplicate entries already present in the list.
- Affiliate links, referral links, or tracking-heavy URLs.

## Entry Format

Entries in the list sections follow this shape:

```markdown
- [Name](https://example.com/) - Short, factual description.
```

The References section is the exception. A bare URL is acceptable there when no
useful description exists.

Mark the status when relevant: `__(Archived)__`, `__(Experimental)__`, or
`__(Research)__`.

Use the canonical project URL when possible, and prefer HTTPS links.

## Pull Requests

Pull requests use a template. Fill in the summary and tick its checklist. The
template holds those rules, so this guide does not repeat them.

## Disclosure

If you are the author, maintainer, or employee behind a resource, say so in the
pull request. Affiliation does not block a contribution. It helps maintainers
weigh how neutral the description is.

Write `None` when you have no relationship with the resource.

## Updating Existing Entries

Corrections are welcome. If a project moved, was archived, changed license, or
has a better canonical URL, please update the existing entry instead of adding a
new duplicate.

If maintainers request changes, update the existing pull request rather than
opening a new one.

Thank you for your suggestions.
